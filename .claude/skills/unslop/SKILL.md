# Unslop for VVeChat

unslop 原作出自 Damir Sokolovsky([@heydamir](https://x.com/heydamir)),他先在 X 上做了 Unslopping 系列。原作按 CC BY 4.0 授权,**任何改编都要保留这份署名**。

这是**为 VVeChat 适配过的版本**:保留了原作的整套方法(先定方向 → 九层红线 → 清单复核 → 报告),但把「什么算 slop」换成了 VVeChat 的标准,并且**把 VVeChat 已经做对的部分明确豁免**。

Vibecoded 的界面失败在同样的地方:到处发光、到处 emoji、间距是当天随手写的、文案在喊。Unslop 修的是手艺,产品本身不动 —— 功能、内容、顺序都留着,变的是每一个尺寸、颜色、字、图标都变成**有意为之**。

去 slop 只是做了一半。一个干净但谁都能用的界面,是下一个模板。每一轮结束,界面要像**只有 VVeChat 才是这样**。

---

## ⚠️ 先读这一节:VVeChat 已经有的东西不是 slop

上游 unslop 是给「从零做界面」的人写的,规则里有不少「不要渐变/不要发光/不要彩色光晕」。**在 VVeChat 里这些是品牌,不是毛病**,照搬会把项目改坏。

| VVeChat 已有的 | 为什么不算 slop |
|---|---|
| **液态玻璃**(`frontend/liquid-glass.js` / `.css`) | 这是产品的招牌:折射、果冻物理、体积光、光照互通。引擎是 `liquid-glass.js`,注册在 `applyLiquidGlass()`。**只管它跑得好不好,不管它存不存在。** |
| **`--accent-grad` 蓝→青渐变** | 用在「我的」气泡、主按钮、头像。渐变只出现在这一个地方是有意的,不是「渐变糊脸」。 |
| **550C 琥珀终端主题** | 硬边、等宽、CRT 质感 —— 那是另一种语言,不是要统一的风格。它**主动关闭液态玻璃**,这是对的。 |
| **squircle 圆角阶梯** | `--r-card:32px / --r-panel:28px / --r-row:20px / --r-ctrl:16px / --r-pill:999px`。上游说「不是所有东西都该是药丸」,VVeChat 已经分了层级 —— 照抄反而会破坏它。 |
| **大圆角 + 真实半透明 + 轻阴影**(无描边分隔) | `:root` 里写得很清楚:「separation comes from blur + shadow, not from strokes」。这是 weightless glass 的核心。 |
| **Qwen 发光环**(`.qwen-ring`)、**Jack 头像光晕**(`.avatar-jack-glow`) | 签名细节,不是装饰性发光。 |
| **群 emoji 头像、官方群 🛡️ 徽章** | 是产品功能(建群时能选),不是「emoji 当图标」的偷懒。 |
| **系统/状态色** `--online/--warn/--danger/--success` | 语义色,必须保持语义。 |
| **登录大字 / 问候语的渐变** | 全产品唯一的「亮一下」时刻。但渐变里不许有紫色,而且不许无限流光 |
| **iOS 风格的小标题**(全大写 + 字距) | 代码里明确写了是 iOS Settings 风格。字号仍然不许低于 11px |
| **550C 开机动画的小字**(9~10.5px) | 那是 CRT 终端序列的质感,一次性的过场,不是工作界面 |

**界线怎么画**:上游说的「渐变/发光/阴影要少而克制」,在 VVeChat 翻译成 —— **一个屏幕里,允许有玻璃、有折射、有光晕,但它们要各自有理由**:玻璃是容器,折射只给少数小卡片(成本高),光晕只给签名元素(助手环、Jack 头像)。**到处都是玻璃光晕 = slop;只有助手环在发光 = 设计。**

其余上游规则(spacing 网格、图标统一、文案不喊、层级靠字号而不是粗细、数字统一格式、动效只解释事情)**在 VVeChat 里全部照用**。

三套主题(浅色 / 深色 / 550C)都要看,同一个改动在 550C 里可能根本不成立。

## Run it

1. **先看见界面。** 别只读代码 —— 读代码会漏掉「看着就别扭但说不清」的东西。
   - **首选:项目自带的 CDP 工具**(能登录、能点、能切主题,截的是真实界面):
     ```bash
     node .claude/skills/unslop/scripts/shot-vvechat.mjs --out shots/xx.png --screen chats --theme light --width 1280
     ```
     `--screen` 可选 `auth|chats|ai|discover|more|group-info|profile`;`--theme` 可选 `light|dark|550c`;`--mobile` 切手机尺寸。
   - 线上站直接看:https://vvechat.onrender.com/ (账号 Jack / Zhr121005)
   - 只有一个链接没代码时,用上游仓库里的 `scripts/snapshot.mjs`(需要 Playwright,只能截公开页面;本仓库没收录,去 heydamir/unslop 取)。
   - 只有一张截图时,先按原样重建成一个静态 HTML 文件,把它当原稿。
2. **审。** 逐条走 [references/signs.md](references/signs.md),每条记一行 + 在哪儿。VVeChat 特有的线索见文件末尾那一节。
3. **决定改多少。** 老实读一遍审的结果再动手。
   - **重 slop**(间距、图标、文案、层级都乱)→ 跑完整流程。
   - **轻 slop**(大体是设计过的,剩几处)→ 只修审出来的地方,方向从现有品牌里取,**别另起炉灶**。更大的想法(缺一个亮点时刻之类的)写进报告当建议,不当改动。
   - **没有 slop** → 直说,最多再给两三条带精确数值的小改进,用户同意才改。**别为了显得不一样而改一个好界面。**
4. **定方向,然后停。** 写下下面那五行。方向一旦定了,后面九层都照着走;改方向等于全部重做。**先把审的结果和方向给用户看,等用户点头再动手**(用户已经说「直接改」就跳过)。
5. **九层,按顺序做。** 一层做完整个屏幕再进下一层。间距最先 —— 节奏对了,别的读起来都不一样了。排版和文案在版式之前(标题多长决定它多大、坐哪)。视觉和动效最后 —— 它们得长在一个已经能用的屏幕上。
6. **核对。** 跑文件末尾的清单,重新截图,跟审的清单逐条对。还在清单上的都得修。
7. **报告**:方向、每层改了什么、写了什么图片提示词。
8. **录屏(用户要才做)**:见 [Story video](#story-video)。

**跑快一点**:一个屏幕最多截三次图来核对。生成图片的话,方向一确认就开始生成,等它的同时继续做前几层。

每一层的精确数值在 [references/tokens.md](references/tokens.md);项目地图、设计语言和豁免清单在 [references/vvechat.md](references/vvechat.md)。

## Direction

动手之前,写五行短句。**从产品本身推出来,不是从最近什么流行推出来。**

- **Product.** 它是干什么的、给谁用,一句平话。
- **Character.** 两三个具体的词,比如 `克制、精确、有点温度` 或 `快、技术感、带点玩心`。**不许用** clean / modern / sleek / minimal / premium —— 这些词形容所有模板。
- **World.** 这个产品天然属于的地方/材质。便签靠近纸和墨,监控工具靠近仪表和夜班,旅行应用靠近地图和窗光。**这个 world 决定中性色的色偏、强调色和视觉素材。**
- **Moments.** 一两个屏幕可以放丰富颜色、材质和细节的地方 —— 要从产品本身长出来:一个渲染出来的对象、一张每个颜色都有意义的图、一个内容里的实物。
- **Signature.** 只有这个产品才会有的小细节,一直用同一处。监控工具的在线状态点,开发者工具的键帽,教学应用的手绘下划线。**一个细节,不是五个。**

### VVeChat 的方向(照这个写,不要每次重推)

- **Product.** 一个聊天本子:找人、找群、聊天,顺带有个能问事的助手。
- **Character.** 轻、透、克制;像一个玻璃盒子,不是一块发光的塑料。
- **World.** 窗边的桌面 —— 半透的玻璃、白天透进来的光、纸质便签的暖调。
- **Moments.** 群头像那一格(全产品唯一的彩色富集区:emoji、渐变、徽章)和**助手的发光环**。
- **Signature.** **Qwen 的发光圆环** —— 黑环套白晕,已经在侧边栏、气泡、@ 选择器里复用了。任何新界面里,凡是「这是助手」,就用这个环,不要另发明一套头像样式。

## 1. Spacing

- 所有间距落在 4px 网格上。margin / padding / gap / 固定高度都是 4 的倍数(28、104 这种也算,不必在表里)。
- 同样的东西同样的大小:列表里所有行同一个高度、同一个间距;一行里的卡片同一个 padding。
- 间距表达分组:**组内间距小于组间间距**。一段文字和它上面那段之间,要比它和下面那段的间距大。
- 对齐成列:图标一列、标签起一条线、数字右对齐一列。**不许用零散的 translate 或奇怪 margin 把某个东西推歪。**
- 密度跟着位置走:窄面板和侧边栏 16,卡片 20~24,页面边距 24~32。
- 导航是整个应用里最密的地方:行高 32~36,行间距 2~4,图标一列,标签一行。
- 小标题离自己那一组更近,离上一组更远:上面 24,下面 8。
- **量一遍侧边栏** —— 间距最容易在侧边栏崩掉。

## 2. Color

- **VVeChat 的中性色已经是调好的**:`--ink / --ink-2 / --muted / --muted-2` 四级文字 + 一套 `--glass-*` 玻璃变量。**用它们,不要再加新的灰。**
- 三个文字角色,不是十个深浅不一的蓝:主 / 次 / 弱。聊天界面里第四个层级就该是灰的了。
- 界面里只有一个强调色(`--accent` / `--accent2`),用得少:主操作、选中态、或者那个真正要紧的数字。
- 玻璃是容器的材质,**不是强调**。想强调某个东西,别给玻璃加光晕 —— 给内容加。
- 语义色只表达语义:绿=在线/成功,黄=警告,红=危险/移除。它们得收着,跟主色坐得住。
- **渐变只允许一处**:`--accent-grad`(我的气泡 / 主按钮 / 头像)。别把它扩散到别的表面。
- 边框是安静的发丝线;深色主题下,深度来自**表面层级**和发丝线,不是阴影。
- 浅色主题的阴影是中性、柔、小的(`--glass-shadow` 那一档就够)。
- **550C 主题里另算**:琥珀色是它自己的世界,别把蓝青强调色带进去。

## 3. Icons

- **一个图标集、一个尺寸、一套线宽。** VVeChat 现在用内联 SVG(line icon),**不要在某几个按钮上突然冒出 emoji**。
- 图标取所在文字角色的颜色(通常次级或弱),不给图标单独上色。
- 图标盒子宽度一致、到标签的间距固定(8 或 10),标签才能对齐。
- **删掉不携带信息的图标**:每个卡片标题前挂一个 emoji、每个分组标题前挂一个 emoji,都是噪音。
- 需要分类色的时候,给一个小的状态点,不要给整块上色。
- 群 emoji 头像、官方群 🛡️ 是**产品功能**,不是「emoji 当图标」,别动。

## 4. Copy

- **中文文案就按中文的口气写,不要翻译腔。**「已发送」不是「Sent successfully」,「群里没人说话」不是「No one has spoken in this group yet」。
- 标题说明这屏是什么、给谁看,用平话,换任何一个产品都装不进去。
- **界面文案里不许有感叹号**,更不许 `!!`。
- 不要「欢迎回来,XXX!👋」这种打招呼标题。标题就是标题。
- 短标签:**搜索**,不是「搜索点什么…」;**群成员**,不是「群成员列表」。
- 变化要说跟什么比:「比上月多 12%」「少了 3 个」。
- 标题、副标题、标签、按钮、说明**结尾不带句号**。只有多句的段落才带。
- 不要「超级」「无缝」「解锁」「魔法」「颠覆」这类词,也不要在任何东西后面挂「AI 助力」。
- 查不了的吹牛(「10 万团队在用」「快 10 倍」)要么让用户确认是真的,要么删掉。**要问就问,别自己编。**
- 假数据要像真的:合理的数字和名字,不要 `[X]`、不要 `123,456`。
- `PRO` / `New ✨` / `Beta 🚀` 这类徽章删掉,除非产品真的需要 —— 需要的话也是安静的文字。

## 5. Type

- **字体族已经定了**:`--font`(系统字体栈)和 `--font-display`。**不要引入第三套字体**,VVeChat 的中文/英文混排靠系统栈在扛。
- 一个字族用于界面,至多再配一个等宽用于数字和 meta。
- 字号从一套阶梯里取,字重 **400 / 500**,600 只在极少的强调处用。**不要 700~900 的粗标题。**
- 层级靠**字号和颜色**,不靠字重。
- 全部句式大小写(中文即:标题不用全大写/不拉开字距)。`PAID THIS MONTH` 这种要写成「本月付费」。
- 小字上不做负字距。小字的可读性靠更大一点、粗一点或松一点。
- 数字用 `tabular-nums`,**全站一个数字格式**:一个写成 `$48,210`,下一个不能写成 `$124,860.40`。
- **不用斜体强调。**

## 6. Layout

- 保持区块和顺序。区块内部的对齐和比例可以为了更清楚而改。
- **这是应用,不是落地页。** 保持真实应用的比例:外壳铺满视口,左侧导航 240~280,内容列流动(上限 ~1440~1600),页面随内容变长。
  - **绝不要把应用缩成一条窄窄的居中列。**
- 上游那套 hero / 场景图 / 分栏文案 —— **VVeChat 用不上**,跳过。
- 手机端:一切按阅读顺序竖排;密集列表在手机上变简单(行更少、列更少),而不是整块缩小;**任何文字不许小于 11px**。
- 聊天界面里内容列是主角:会话列表是导航,助手列表也是导航,别让它们比消息更抢眼。

## 7. Details

- **嵌套圆角 = 外圆角 − 内边距**,且不小于 4。
- 控件 8~10,卡片 12~16,面板 14~20 —— 但 VVeChat 已经有一套(`--r-ctrl/--r-row/--r-card/--r-panel/--r-pill`),**用它的,别另起一套**。
- 不是所有东西都该是药丸。计数和 meta 变成安静的文字(常常是等宽 + 弱色),不要发光的药丸。
- 键盘快捷键做成小键帽。
- 聊天气泡:自己的和对方的要有明确区分(实心渐变 vs 半透明玻璃),但两边的圆角、间距、字号必须一致。
- 状态是表面层级 + 发丝线高亮,不是带光晕的渐变。
- 焦点态要看得见(键盘用户)。
- 一个状态点、一张头像、一个徽章 —— **一个细节,不是五个**。

## 8. Visuals

- **VVeChat 是应用,几乎不需要生成图片。** 它的「时刻」来自产品本身:群头像那一格、Qwen 的环、消息气泡里的真实内容。
- 装饰性填充物删掉:发光球体、星云、悬浮方块、全息机器人。聊天界面里没有它们的容身之地。
- **物理的东西用代码画**:支付卡可以用代码画(软渐变 + 芯片 + 数字),别去生成图片。
- 真要生成图,只用在:空状态、引导页、营销时刻。
- 参考品质(构图、光、克制)在 [references/refs.md](references/refs.md),特效写法在 [references/effects.md](references/effects.md),选材在 [references/visuals.md](references/visuals.md)。

## 9. Motion

- 删掉**没有理由的循环动效**:不是活的东西就别 pulse/shimmer,标题别呼吸,元素别漂浮。
- 删掉 `transition-all`、弹跳弹簧、卡片 hover 放大。
- **保留解释事情的动效**:hover 是快速的颜色/表面变化,press 是一点点缩小,菜单从它打开的地方淡入并升高几像素,变化的数字会补间。
- 只过渡 `color / background / border / opacity / transform`,并且写明属性。**不要动画 width/height/top/left/margin/大 blur** —— 弱设备上会卡。
- 全屏一套缓动曲线、几个时长。反馈用短的,进场用稍长的。
- 加载最多一个入场:主内容短淡入 + 一点点错峰。

把一个屏幕「自己变干净」的过程录成短视频:红色红线标出 slop,每一步只改 CSS,让数值自己补间过去。

- 页面用 1440 宽、至少 900 高,别用 100vh。
- 三到五步,合并成看得见变化的几个:Spacing → Color and icons → Type and copy → Details。

- **VVeChat 用这个要小心**:它是应用不是落地页,story 价值有限。用户明确要再录。

## Do not

- 不要改产品本身:功能、内容、区块顺序都留着,除非用户要更多。
- 不要在**一个界面里**堆多个亮点时刻。
- 不要把删掉的装饰换成新装饰,也不要换个时髦词接着堆(玻璃、噪点、霓虹、bento 网格)。
- 不要发明功能、吹牛或造假数据。
- 不要每个产品都用同一张脸。方向决定调色和字体,不是习惯。
- **VVeChat 专项禁令**(比上游更严,因为这些东西在别的项目里才算 slop,在这里是品牌):
  - **不要删液态玻璃层**,也不要把玻璃从容器上拿掉。
  - **不要把 `--accent-grad` 拆成纯色**。它就这一处,留着。
  - **不要动 550C 终端主题的硬边和等宽字体**,也不要在里面加玻璃。
  - **不要把 Qwen 的发光环换成字母头像**,也不要在别处新造一套发光头像。
  - **不要为了「统一」把群 emoji 头像换成字母。**
  - 不要动 `--r-*` 圆角阶梯的层级关系。
